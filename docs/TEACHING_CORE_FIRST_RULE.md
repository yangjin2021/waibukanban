# 教学顺序补充规则：核心优先，解释后置

更新时间：2026-08-09

> 本文件记录用户最新明确教学偏好。它是 `docs/TEACHING_SOP.md` 的高优先级补充规则；若展示顺序与旧 SOP 冲突，以本文件为准。

## 1. 核心原则

以后每一课、每一次代码讲解，都必须把**重点、核心内容、核心代码、最终代码**放在最前面。

默认顺序：

```text
① 本课最重要的一句话
↓
② 本课核心代码 / 最简核心代码
↓
③ 当前课完整最终代码（适合时）
↓
④ 本课真正新增的约 15% 知识
↓
⑤ 核心数据流 / 核心结构图
↓
⑥ 后续全部内容用于解释前面的核心
```

也就是说：

> **先给答案与核心，再解释为什么。**

不能把最重要的代码、最终结构或本课新增能力埋在课程中后段。

---

## 2. 后半部分的职责

核心内容出现之后，后续内容只负责帮助用户读懂、验证和建立直觉，例如：

```text
逐行展开
真实数据代入
变量 / 参数 / return 数据流
PyCharm 颜色与 token 属性
[] / () / {} / : / , / . 等符号解释
嵌套结构图
数据流箭头图
for 循环逐轮图
if / else 分支图
函数输入 → 处理 → 输出图
为什么这样写 / 不这样写会怎样
比喻
代码哲学
Poker AI 项目连接
练习与诊断
```

这些都是对前面核心内容的**解释层**，不能反过来抢占核心位置。

---

## 3. 与“85% 旧知识 + 15% 新知识”的结合

“核心优先”不改变螺旋式课程设计。

每堂课仍然：

```text
上一课已经建立的整体能力 ≈ 85%
+
本课新增能力 ≈ 15%
```

但展示时要先直接告诉用户：

```text
这一课最终要会什么？
上一课基础上新增了什么？
最终代码长什么样？
```

然后再从后面逐层解释这些内容。

---

## 4. 用户提问时也执行核心优先

用户问某一行代码时，优先顺序：

```text
先直接说这一行是什么意思
↓
给最小替换 / 真实值
↓
再判断暴露了哪个基础缺口
↓
后面补解释、图、类比、符号、数据流
↓
最后回到原代码
```

不要先铺很长背景才告诉用户答案。

---

## 5. 练习的位置

交互题 / 小测用于测量掌握情况，不作为默认的内容解锁门槛。

默认：

```text
核心内容全部可见
↓
解释过程中穿插小题
↓
最后统一诊断
↓
结果决定下一课 85% 复用什么、15% 新增什么
```

---

## 6. 一句话规则

> **重点和核心永远放前面；后面的颜色、符号、图、数据流、类比、逐行展开、练习和代码哲学，全部用于解释前面已经给出的核心。**
