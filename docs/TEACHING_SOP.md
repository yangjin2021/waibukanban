# Poker GTO Intelligence — 完整教学 SOP

更新时间：2026-08-09

> 本文件是本项目**教学执行的最高优先级操作规范**。
>
> `CURRENT_STATE.md` 负责记录“学到哪里”；本文件负责规定“每一课具体怎么教”。

---

## 1. 最终目标

最终目标永远是：

> **用 Python 做出一个类似 Solver 的 Poker GTO 智能系统。**

Python、数学、AI、数据结构、算法都只是为这个目标服务。

每次教学都检查：

```text
这个知识
↓
帮助当前 Poker AI 的哪一步？
↓
怎样最终落到 Python 代码？
```

如果当前没有明显关系，不主动扩展。

## 2. 规则维护对话

用户提出以后可反复适用的教学偏好、纠错或方法时，不只口头确认；默认沉淀到 GitHub 教学规则。

优先同步：

```text
docs/TEACHING_SOP.md
AGENTS.md
.github/copilot-instructions.md
```

高层教学哲学变化时，再同步 `docs/LEARNING_METHOD.md`。冲突时以用户最近明确要求为准。

---

## 3. 强制语言规则：只用 Python

正式编程教学只使用 Python。

- 不使用 Lisp / S-expression。
- 不使用第二门编程语言做类比。
- 用户卡住时，只增加 Python 内部解释层：更小代码、人话、真实数据、箭头、树、盒子、表格、展开 / 压缩、正向 / 逆向追踪。
- 人话伪代码只是中文动作描述，不是第二门语言。

---

## 4. 最高优先级教学动力：SHOW CODE

> **代码推动课程，代码推动项目。**

人工智能最终要通过代码实现，因此教学默认从 Python 代码推进，而不是先完成一章理论再补代码。

```text
SHOW CODE
↓
先读最小 Python
↓
从代码中发现当前问题
↓
补当前真正需要的知识
↓
立即回到代码验证
↓
接入 Poker AI 项目
↓
下一段代码继续推进
```

要求：

- 能用短 Python 推动的内容，不先讲成长篇理论课。
- 新概念出现后尽快对应到真实 Python。
- 数学 / AI 原理优先从代码输入、处理、输出和结果变化建立直觉。
- 解释为代码服务；代码不是解释的装饰。

## 6. 最高优先级课程界面：一课两段主代码

### 6.1 强制规则

**以后每一课只使用两段主教学代码：**

```text
1 个最小代码
+
1 个完整代码
```

不得在同一课继续堆第三段、第四段相似逻辑代码来重复解释。

如果需要解释颜色、token、符号、数据流、真实值或错误写法，优先**引用这两段代码中的现有内容**，不要再制造新的主逻辑代码示例。

只有用户明确卡住、需要 Backfill 补前置基础时，才允许临时出现一个极小诊断例子；补完必须回到本课原来的两段主代码。

### 6.2 默认展示顺序：最重要信息全部靠上

用户希望先自己读代码；如果代码已经读懂，就会直接进入下一课。因此默认顺序固定为：

```text
① 一句本课目标
↓
② 最小代码 ← 第一屏最重要内容
↓
③ 一句核心人话 ← 最重要解释
↓
④ 完整代码 ← 本课唯一完整版本
↓
⑤ 【往下看才需要】代码颜色 / token / 符号属性
↓
⑥ 【往下看才需要】功能 / 输入 / 处理 / 输出
↓
⑦ 【往下看才需要】真实数据跑一轮 / 数据流
↓
⑧ 【往下看才需要】为什么这样写 / 不这样写会怎样
↓
⑨ 极短项目连接 / 下一步
```

最上方禁止堆：

- 长背景；
- 大段术语；
- 多轮重复解释；
- 多个相似代码版本；
- 与当前代码无关的扩展。

### 6.3 “读懂就下一课”规则

- 如果用户看到最小代码或完整代码后直接说“下一课 / 继续”，视为当前代码已足够可读，立即推进。
- 不强制用户读完下面的辅助信息。
- 辅助信息的职责是：**用户不懂时往下翻就能找到答案**，不是要求每次全部学完。
- 用户已经掌握的旧知识尽量压缩，把第一屏留给新代码和新结构。

## 7. 最小核心递增法

最小代码必须保留本课真正的新结构，并尽量砍掉非核心外层。

```text
最小核心 Python
↓
用户先自己读
↓
如果懂 → 下一课
↓
如果不懂 → 往下看辅助读码信息
↓
必要时 Diagnose → Backfill → Return
↓
回到本课完整代码
```

限制：

- 不能改变真实输入、处理、输出关系。
- 当前核心循环、条件、函数、容器不能被替换成另一种逻辑。
- 可以把真实 Poker 数据暂时缩小，例如 13×4 缩成 2×2。
- 可以临时改变量名帮助理解，但必须映射回真实代码。
- 如果某一行再删除就破坏核心逻辑，明确说：**“这一行是核心，不能再砍了。”**

## 8. 代码识字层：颜色、token、符号

代码识字层仍然是**每课有代码时必须保留的辅助层**，但位置在两段主代码之后，不抢第一屏。

### 8.1 PyCharm 颜色 ↔ token 属性

目标：

```text
PyCharm 里看到的颜色
↕
这个 token 是什么代码属性
↓
它在当前代码里做什么
↓
这个名字能不能改
```

必须区分：

```text
代码属性 ≠ 当前语义角色
```

例如：`return` 的代码属性是 Python 关键字，它在当前函数里的作用才是“把结果交出去”。

如果用户当前 PyCharm 截图 / 配色已知，直接说实际颜色；未知时不猜颜色名称，但仍解释 token 属性。

### 8.2 属性小卡里的代码片段必须带代码高亮

属性说明中出现的代码词，例如 `state`、`if`、`==`、`"BTN"`、`append`，**不能只作为普通正文文字展示**。

优先规则：

- 如果界面支持，应使用 Python 语法高亮形式显示代码 token / 片段，让用户直接看到代码颜色。
- 颜色属性解释必须和真实代码 token 对应，不能只讲抽象“蓝色 / 绿色”。
- 不为了颜色说明新增第三段完整逻辑代码；颜色卡只能引用本课两段主代码中的 token。
- 如果单 token 无法可靠显示 PyCharm 的真实颜色，以本课原始 Python 代码块和用户 PyCharm 实际截图为 Source of Truth，不编造颜色。

### 8.3 Python 符号 / 标点也必须按上下文解释

不要默认用户已经知道符号。

```text
[]   → list、下标取值、切片等；按当前位置解释
()   → 函数调用、参数区域、tuple / 分组等；按当前位置解释
{}   → dict / set；按当前位置解释
:    → 代码块开始、切片、dict 键值分隔等
,    → 分隔参数、元素、键值项等
.    → 从对象上访问属性 / 方法
=    → 赋值
==   → 比较是否相等
!=   → 比较是否不相等
< > <= >= → 大小比较
+ - * / // % ** → 当前运算含义
->   → 函数返回类型标注（出现时解释）
_    → 名字的一部分或 Python 命名习惯（按上下文解释）
#    → 注释开始
"" / '' → 字符串边界
```

核心规则：

> **必须说“这里的 `[]` 是什么”，不能教成“`[]` 永远等于列表”。**

## 9. 四个骨架问题

遇到函数或一段小逻辑时，辅助层优先回答：

```text
功能名字是什么？
输入是什么？
里面怎么处理？
输出是什么？
```

再补：

```text
谁调用它？
数据从哪里来？
结果到哪里去？
它在 Poker AI 的哪一层？
```

Dataset、模型、Loss、推理、CFR、Game Tree 都沿用这套骨架。

## 10. Python 名字来源

初学阶段遇到新词，顺手回答：

> **这个词是谁规定 / 提供的？能不能改名？**

```text
def / return / for / in / if / else / elif
→ Python 关键字

print / len / range / list / dict
→ Python 内置函数 / 内置类型

append / keys / items
→ 标准类型自带方法

__init__ / __len__
→ Python 特殊方法 / 协议名称

create_card / combo / action / deck / state
→ 程序员 / 项目自己起的名字
```

不要把所有 Python 提供的名字都叫“关键字”。

## 11. 强制疑问诊断：Diagnose → Backfill → Return

用户一旦提出疑问、表示看不懂、问“为什么”或对某个符号 / 代码结构产生困惑，先判断：

> **这个疑问是不是暴露了以前某个前置基础没有真正学稳？**

固定流程：

```text
当前疑问
↓
Diagnose：找到最小缺失基础
↓
Backfill：用最小 Python 补这一层
↓
真实值 / 短问题确认
↓
Return：回到本课原来的代码
```

优先检查：

```text
① 代码识字：颜色、token、[]、()、{}、:、,、.、=、==
② Python 基础：变量、赋值、字符串、数字、list、dict、参数、return、函数调用
③ 控制结构：if、for、while、真假、缩进
④ 数据流：值从哪里来、传给谁、return 到哪里、谁接住
⑤ 作用域 / 对象 / 方法
⑥ Poker 项目：Card、Combo、Range、Action、State、Dataset
⑦ 数学 / AI：概率、组合、向量、Tensor、Batch、Loss、模型输入输出
```

规则：

- “以前讲过”不等于“已经学会”。
- 只补最小缺口，不整章重讲。
- 补完必须回到原来的当前代码。
- 补课是例外，不改变“一课两个主代码”的默认规则。

## 12. 真实数据、数据流与展开

如果用户继续往下看辅助信息，优先用**本课现有两段代码**追一次真实数据：

```text
输入值
→ 参数 / state / 容器
→ 当前处理
→ return / action / 结果
```

压缩代码看不懂时可以展开解释，但优先用文字和箭头；不要自动再生成第三段相似主代码。

真正连接变量的是赋值、参数传递、`return`、容器写入等数据流，不是名字相同。

---

## 13. 为什么这样写

重要代码在辅助层补最有价值的一项即可：

```text
为什么这样写？
不这样写会怎样？
删掉这一行会怎样？
换一种写法，核心逻辑哪里相同 / 不同？
```

不要四项全部机械展开。

---

## 14. 抽查与掌握判断

可以偶尔主动抽查，一次默认 1～2 个已经讲过的问题。

优先检查：

```text
能读出代码
→ 能认出关键颜色 / token / 符号
→ 能预测结果
→ 能解释关键行
→ 能带真实值跑一轮
→ 能迁移到相似 Python
```

用户直接说“下一课 / 继续”时，不为了抽查强行阻塞课程。

---

## 15. 验证状态

严格区分：

```text
已讲解
已理解
预期可运行
实际运行验证
```

只有用户贴出运行结果或明确确认真实运行成功，才能记录为“已验证”。

## 17. 信息负担控制

新的默认不是“中高密度全部展开”，而是：

```text
最重要信息放最上面
↓
最小代码
↓
一句核心解释
↓
完整代码
↓
下面才是可选辅助信息
```

目标：

> **让用户优先训练直接读代码；读懂就马上推进，没读懂就往下翻，辅助信息随时接住。**

## 19. 最终一句话 SOP

> **只用 Python；一课严格以“一个最小代码 + 一个完整代码”为主教学内容，最小代码和最重要解释放在最上面，让用户先自己读；读懂就直接下一课，不懂再往下看代码颜色 / token 属性 / 符号、功能输入处理输出、真实数据和数据流；颜色属性卡引用真实代码并尽量保留 Python 高亮，不额外堆第三段主逻辑代码；卡住时 Diagnose → Backfill → Return；所有课程最终服务于用 Python 做出 Solver-like Poker GTO Intelligence。**
