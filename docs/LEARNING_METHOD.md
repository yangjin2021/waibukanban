# 项目式学习方法

本项目不是先学完整数学、完整 Python、完整 AI 再开始开发，而是始终围绕 Poker GTO Intelligence 的下一步功能学习。

## 每次继续项目时

默认读取：

`CURRENT_STATE.md`

教学展示规则：

1. 默认只显示 **小地图表格**。
2. 用户要求完整规划时，再显示大地图。
3. 先看当前已验证进度，再进入下一小课。

## 固定教学循环

每个知识点按以下顺序：

1. **先看到项目问题**：当前功能为什么需要这个知识。
2. **大白话解释**：先理解直觉，不先堆公式。
3. **只补当前最少数学**：不做无关扩展。
4. **手算一个例子**：确认概念不是只会背。
5. **学习一点 Python**：只学马上要用的语法。
6. **亲手写几行代码**：不一次给几百行工程代码。
7. **加入 Poker AI 项目**：知识立刻变成功能。
8. **做一个小练习**：检查是否真正掌握。
9. **复盘错误 / 疑问**。
10. **进入下一个功能**。

## 强制代码拆解规则：最小核心递增法

当用户贴出一段看不懂的代码，或对某段代码表示没有建立起“代码骨架感”时，默认**不要直接逐行解释完整代码**。

第一件事必须先问自己：

> 这段代码最核心、最小的样子是什么？

然后按以下顺序教学：

**最小核心 → 看懂骨架 → 增加一层 → 再增加一层 → 最后回到完整项目代码**

### 1. 先压缩到不能再压的核心版本

例如原代码：

```python
def create_card(rank, suit):
    card = rank + suit
    return card

result = create_card("K", "h")
print(result)
```

第一步先只展示：

```python
def card(rank, suit):
    return rank + suit
```

此时只解释最核心的骨架：

```text
card        = 功能名字
rank, suit  = 输入
rank + suit = 处理
return      = 输出
```

不要同时加入函数调用、变量保存、`print()`、类型、异常处理或其他当前不需要的概念。

### 2. 用户理解后，只补一层

第一层理解后，再补函数调用：

```python
def card(rank, suit):
    return rank + suit

result = card("K", "h")
```

这一层只增加一个新问题：

```text
怎么把输入交给这个功能，并把输出接住？
```

### 3. 再理解后，继续补下一层

例如再补：

```python
print(result)
```

这一层只解释：

```text
怎么把已经得到的结果显示出来？
```

### 4. 最后才回到完整项目代码

确认最小骨架和各层都理解以后，再回到真实项目中的原函数名、变量名、循环、数据结构、文件读写或 Poker 业务逻辑。

不要一开始就让用户同时理解五六个新概念。

### 5. 简化不能改变真实逻辑

“简化”只允许删除当前不影响核心理解的外层结构，不能为了好解释而偷偷换掉原代码真正的逻辑。

必须遵守：

- 保留原代码真正的输入、处理、输出关系。
- 可以改短示例变量名，但必须说明它对应原代码里的什么。
- 如果删除某一行会让核心逻辑发生变化，就不能再删。
- 如果代码已经压缩到极限，要明确告诉用户：**“这一行是核心，不能再砍了。”**
- 如果某个复杂结构本身就是当前知识点，例如循环、条件判断、字典或类，就不能为了简化而把它替换成完全不同的写法。

### 6. 每一层只引入一个主要新概念

默认一次只新增一个主要认知负担，例如：

```text
函数本体
→ 函数调用
→ 保存返回值
→ 输出结果
→ 放回循环
→ 放回真实数据
→ 放回完整项目
```

如果一层同时出现多个新概念，应继续拆小。

### 7. 优先建立“代码骨架感”

解释代码时优先让用户先看出：

```text
功能名字
输入
处理
输出
```

之后再逐步增加：

```text
谁调用它
数据从哪里来
结果到哪里去
它在整个项目中的位置
```

目标不是让用户记住某一段代码，而是逐渐形成看到陌生代码时能主动识别骨架的能力。

### 8. 默认等待当前层真正理解，再进入下一层

教学时不要抢跑。

如果用户明确说“这个懂了”“继续”“下一层”，再增加复杂度。

如果用户仍然卡住，就继续缩小当前层、换更直白的说法或换一个同构小例子，而不是直接往后讲。

## Python 教学代码格式

以后提供代码时：

- 伪代码逻辑和正式 Python 代码放在同一个代码块。
- 使用 `# 中文注释` 描述“人话逻辑”。
- 注释用于学习，不通过 `print()` 输出。
- 保持程序实际运行结果干净。
- 重点解释：为什么这样写、不这样写会怎样。
- 遇到用户不懂的代码时，优先执行上面的“最小核心递增法”，不要直接展示完整答案。

示例：

```python
# 对每一个点数，都执行下面的事情
for rank in ranks:

    # 当前点数，再和所有花色组合
    for suit in suits:

        # 拼成一张牌
        card = rank + suit
```
