# 项目式学习方法

更新时间：2026-08-09

## 0. 永远不要忘记最终目标

本项目学习 Python 不是为了“学完一门语言”，最终目标始终是：

> **用 Python 做出一个类似 Solver 的 Poker GTO 智能系统。**

以后所有学习内容都要回答：

> **这个知识怎样通过 Python 帮助最终 Poker Solver-like AI？**

路线：

```text
Python 基础
→ Poker 数据结构
→ Card / Range / Action / State
→ Solver 数据读取与自动化
→ Dataset
→ NumPy / PyTorch
→ 模型训练与评估
→ Game Tree / CFR
→ 推理与决策
→ 类 Solver 的 Poker GTO 智能系统
```

## 1. 只用 Python 教学

正式编程教学只使用 Python。

- 不使用 Lisp / S-expression 或第二门编程语言做类比。
- 卡住时改用更小 Python、人话、真实数据、箭头、树、盒子、表格、比喻、展开 / 压缩、正向 / 逆向追踪。
- 所有正式 AI / 工程实现最终回到 Python。

## 2. 核心哲学：Code drives learning

> **代码是推动课程与项目的第一动力。**

人工智能最终要通过代码实现，所以不把代码当理论课最后的“例子”，而是让代码成为知识出现的入口。

```text
SHOW CODE
→ 读代码
→ 遇到问题
→ 补当前需要的知识
→ 回到代码验证
→ 接入 Poker AI
→ 下一段代码继续推进
```

项目进度优先问：

> **今天又读懂、写出、运行或验证了哪段 Python？**

## 3. 每课固定三类辅助

以后每一课除了主代码外，都固定保留三类辅助：

```text
① 代码识字
→ PyCharm 颜色 + token 属性 + 符号 + 名字来源

② 理解镜头
→ 真实数据 + 数据流 + 比喻 / 解释

③ 代码哲学
→ 当前代码背后的编程思想 / 工程直觉
```

这些内容可以紧凑，但不完全省略。目标是让用户不仅知道“代码运行了什么”，还逐渐知道“代码怎么看、为什么这么组织、这种结构以后还会在哪里出现”。

## 4. 代码识字能力是基础能力

目标不仅是懂程序逻辑，还要逐渐做到：

> **看到 Python 代码表面，就能读出大部分元素是什么。**

因此每课辅助识别：

```text
PyCharm 颜色
代码单词 / token 属性
Python 符号 / 标点
名字是谁规定的、能不能改
```

例如：

```text
def      → Python 关键字
rank     → 参数 / 变量名
append   → list 方法
"As"     → 字符串字面量
[]       → 当前上下文中的 list / 下标 / 切片
()       → 当前上下文中的调用 / 参数 / 分组等
{}       → 当前上下文中的 dict / set
=        → 赋值
==       → 比较是否相等
.        → 访问对象属性 / 方法
```

尤其注意：**符号必须结合上下文解释。** `[]` 不能永远死背成“列表”。

如果用户当前 PyCharm 配色已知，直接说明实际颜色；未知时不猜颜色名称，但仍解释 token 属性。

## 5. 比喻必须回到代码

每课至少给一个能帮助理解当前代码的比喻 / 解释镜头，例如：

```text
座位编号
抽屉 / 盒子
流水线
快递交接
菜单 / 点单
扑克桌上的实际动作
```

比喻只负责建立直觉，之后必须明确映射回真实 Python。不能为了好懂而改变真实执行顺序、数据流或语义。

## 6. 代码哲学逐课积累

每课后半段补 1～2 个直接对应当前代码的思想，例如：

```text
数据比名字更重要
结构比记忆更重要
索引是位置，不是内容
函数是在给处理建立边界
参数让函数可复用
return 是函数的对外出口
循环是在把同一个规则应用到不同数据
条件是在程序中制造分叉
抽象是为了减少重复和错误
Small → Correct → Scale
可读代码首先是给人读
AI 工程仍然是数据 → 处理 → 输出
```

不讲空泛口号，要指出它对应当前代码里的哪一行 / 哪个结构。

## 7. 疑问先诊断前置缺口

用户出现疑问时，先问：

> **这是真的新知识难，还是以前某个基础没有学稳？**

默认采用：

```text
Diagnose
↓
找到当前疑问依赖的最小前置缺口
↓
Backfill
↓
用短 Python 补上
↓
Return
↓
重新回到原来的当前代码
```

优先检查：代码识字、Python 基础、控制结构、数据流、作用域 / 对象 / 方法、Poker 项目基础、数学 / AI 前置。

原则：**讲过不等于学会。** 只补最小缺口，不整章重讲。

## 8. 最小核心递增法

看不懂时先缩代码：

```text
真实代码
→ 最小核心 Python
→ 读懂代码表面
→ 颜色 / token / 符号
→ 功能 / 输入 / 处理 / 输出
→ 真实值跑一轮
→ 比喻 / 解释
→ 代码哲学
→ 逐层还原
→ 回到项目
```

如果某行再删除就破坏核心逻辑，要明确说：

> **这一行是核心，不能再砍了。**

简化不能改变真实逻辑。

## 9. 四个骨架问题

每个函数优先识别：

```text
功能名字
输入
处理
输出
```

再看：

```text
谁调用它
数据从哪里来
结果到哪里去
它属于 Poker AI 的哪个更大功能
```

Dataset、Model、Loss、推理、CFR、Game Tree 都继续沿用这套骨架。

## 10. 真实数据与数据流

抽象代码尽量拿真实 Poker 数据跑一次。

真正连接变量的是赋值、参数传递、`return`、容器写入等数据流，不是名字一样。

以后 Dataset、Tensor、Model Input、Policy、EV 都用同样的数据流思维理解。

## 11. 数学和 AI 按代码需要出现

不为了“完整课程”提前堆理论。

```text
Python 代码出现需求
→ 补最少必要数学 / AI 概念
→ 马上用 Python 表达
→ 跑数据
→ 看输出
→ 接回 Poker AI
```

例如：

```text
百分数        → Range Frequency
概率          → Strategy
组合          → 1326 Combos
加权平均      → Range EV
向量          → Policy / Range
矩阵          → Batch / Dataset
函数          → Model(x) = y
误差          → Loss
导数          → Gradient
概率分布      → Softmax
条件概率      → Range Update
博弈树 / Regret → CFR
```

## 12. 每次学习都变成项目资产

每次课程尽量留下：Python 代码、测试、数据样本、模型、实验记录、文档或当前进度更新。

每完成一个可验证小步骤，优先更新 `CURRENT_STATE.md`。

## 13. 一句话路线

> **SHOW CODE；让 Python 代码成为课程与项目的第一动力；每课固定用 PyCharm 颜色、token 属性、符号和名字来源帮助读代码，再用真实数据、比喻和解释建立直觉，并逐课补充代码哲学；用户一有疑问就 Diagnose → Backfill → Return；每学会一点都放回 Poker AI 项目。**
