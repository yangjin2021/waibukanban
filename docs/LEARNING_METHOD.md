# 项目式学习方法

更新时间：2026-08-08

## 0. 永远不要忘记最终目标

本项目学习 Python 不是为了“学完一门语言”，最终目标始终是：

> **用 Python 做出一个类似 Solver 的 Poker GTO 智能系统。**

以后所有学习内容都要不断回答一个问题：

> **这个知识以后怎样帮助我们把 Python Poker Solver-like AI 做出来？**

如果一个知识目前和这个目标没有明显关系，不主动扩展；等项目真正需要时再学。

路线固定为：

```text
Python 基础
→ Poker 数据结构
→ Card / Range / Action / State
→ Solver 数据读取与自动化
→ Dataset
→ NumPy / PyTorch
→ 模型训练与评估
→ Game Tree / CFR 等需要的算法知识
→ 推理与决策
→ 类 Solver 的 Poker GTO 智能系统
```

## 1. 只用 Python 教学

从现在开始，正式编程教学只使用 **Python**。

- 不再使用 Lisp / S-expression 辅助教学。
- 不为了“换个角度”引入第二门编程语言。
- 结构看不懂时，改用：最小 Python、人话伪代码、箭头、树、盒子、表格、真实数据跑一轮。
- 人话伪代码只是中文动作流程，不是一门新的编程语言。
- 除非用户以后明确主动修改这条规则，否则不要重新引入其他语言教学。

目标是减少认知切换，把所有精力集中到 Python 与最终 Poker AI 工程上。

## 3. 核心教学哲学

目标不是背代码，而是形成稳定的“代码骨架感”：

```text
看到代码
→ 认出骨架
→ 找到输入
→ 看懂处理
→ 找到输出
→ 看懂数据流
→ 压缩成最小核心
→ 一层层还原
→ 能迁移到新的 Python 代码
→ 最后用于 Poker AI 项目
```

每个函数优先识别：

```text
🟦 功能名字
🟩 输入
🟨 处理
🟥 输出
```

再看：

```text
谁调用它
数据从哪里来
结果到哪里去
它属于 Poker AI 的哪个更大功能
```

## 4. 最小核心递增法

遇到看不懂的代码，不直接从完整工程代码开始堆解释。

固定顺序：

```text
完整 Python
→ 砍到最小核心 Python
→ 看懂骨架
→ 只增加一层
→ 再增加一层
→ 回到完整项目 Python
```

如果某行再删除就会改变核心逻辑，要明确说：

> **这一行是核心，不能再砍了。**

简化不能改变真实逻辑。

## 5. 人话伪代码高频辅助

稍复杂的 Python 可以先翻译成中文动作流程：

```text
准备 13 个点数
准备 4 个花色
准备一个空 deck

每个点数
    搭配每个花色
        做成一张牌
        放进 deck

最后得到 52 张
```

然后再回到真正的 Python。

要求：

- 一行尽量一个动作。
- 缩进对应真实 Python 层级。
- 执行顺序、条件、循环、数据流不能被改掉。
- 已经能直接看懂时，不机械增加伪代码。

## 6. 六镜头教学法（全部围绕 Python）

重要新结构默认从下面六个角度中选择最需要的几个：

```text
① 正式、干净、可运行的 Python
② 最小核心 Python
③ 颜色 / 角色骨架
④ 人话执行流程
⑤ 树 / 层级 / 数据流结构图
⑥ 真实数据实际跑一轮
```

卡住时再使用：

```text
压缩版 ↔ 展开版
正向执行 ↔ 逆向追踪
```

这些镜头都是为了更容易读懂 **同一段 Python**，不是为了增加新的语言。

## 7. 固定语义颜色

| 标记 | 角色 |
|---|---|
| 🟦 | 功能 / 函数名字 |
| 🟩 | 输入 / 参数 |
| 🟨 | 处理 / 表达式 |
| 🟥 | 输出 / 返回结果 |
| 🟪 | 循环 / 条件 / 控制结构 |
| 🟧 | 数据容器 / 局部变量 / 状态 |

原则：

> **同一个结构角色，同一种教学颜色。**

颜色只是视觉辅助，不能替代文字解释。

## 8. Python 名字来源要标清

遇到新名字时顺手说明：

```text
def     = 开始定义函数【Python 关键字：规定好的】
card    = 函数名字【程序员自己起的，可以换】
return  = 把结果交出去【Python 关键字：规定好的】
print   = 显示内容【Python 内置函数】
append  = 往 list 末尾放东西【list 自带方法】
```

重点帮用户判断：

> **这个必须这么写吗？这个名字能不能换？**

不要把关键字、内置函数、类型方法、特殊方法、标准库、第三方库名称混成一类。

## 9. 教学变量名先服务理解

两个变量不是同一个变量时，如果同名容易产生假联系，教学示例先用不同名字。

例如：

```python
def create_deck():
    local_deck = []
    return local_deck

received_deck = create_deck()
```

优先语义名字；实在不好取时，教学中宁可暂时用 `deck` / `deck2`。

真实项目如果本来合法使用同名变量，不擅自修改；先用教学名字讲懂，再明确映射回原代码。

## 10. 主动抽查与掌握验证

可以偶尔主动抽查，一次默认 1～2 个已经讲过的短问题。

优先检查：

```text
认出骨架
→ 预测结果
→ 解释原因
→ 知道删一行会怎样
→ 换一个相似 Python 例子还能使用
```

答错时先给小提示，必要时退回最小核心；不要立刻把完整答案贴出来。

## 11. 数学和 AI 都按项目需要出现

不单独为了“完整课程”提前堆知识。

```text
百分数        → Range Frequency
概率          → Strategy
组合          → 1326 Combos
加权平均      → Range EV
向量          → Policy / Range
矩阵          → Batch / Dataset
函数          → Model(x) = y
平方 / 误差   → Loss
导数          → Gradient
链式法则      → Backpropagation
概率分布      → Softmax
条件概率      → Range Update
博弈树 / Regret → CFR / Solver-like 决策
```

出现一个知识时，要尽量连接回最终 Poker AI，而不是孤立学习。

## 12. 每次学习都要变成项目资产

每次课程至少尽量留下一个可追踪成果：

- Python 代码
- 测试
- 数据样本
- 模型
- 实验记录
- 文档
- 当前进度更新

每完成一个可验证小步骤，优先更新 `CURRENT_STATE.md`。

## 13. 一句话路线

> **只学当前 Poker AI 下一步真正需要的知识；只用 Python 落地；看不懂就砍到最小核心并用人话、图和真实数据解释；每学会一点都放回项目，最终做出一个类似 Solver 的 Python Poker GTO 智能系统。**
