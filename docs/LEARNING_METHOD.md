# 项目式学习方法

更新时间：2026-08-08

本项目不是先学完整数学、完整 Python、完整 Lisp、完整 AI 再开始开发，而是始终围绕 Poker GTO Intelligence 的下一步功能学习。

当前课程采用：

```text
Python 主线 + Common Lisp 同步教学副线
```

Python 负责真正的 Poker GTO AI 工程；Common Lisp 用已经会的 Python 帮助重新观察函数、表达式、列表、递归、树、符号与 code-as-data。

Lisp 默认在 GPT 内教学，不要求接入本地 Poker 项目。

## 1. 文档分工

以后教学规则不再散落维护。


以后新增：颜色规则、视觉化方法、比喻、代码拆解方法、执行追踪方法等，优先更新 SOP，而不是在多个文档中复制不同版本。

## 2. 核心教学哲学

目标不是背某段代码，而是形成：

```text
看到代码
→ 认出骨架
→ 找到输入
→ 看懂处理
→ 找到输出
→ 看懂数据流
→ 能压缩成最小核心
→ 能一层层还原
→ 能迁移到新代码
```

每个函数优先识别：

```text
🟦 功能名字
🟩 输入
🟨 处理
🟥 输出
```

再看：

```text
谁调用它
数据从哪里来
结果到哪里去
它属于哪个更大的功能
```

## 3. 最小核心递增法

遇到看不懂的代码，不直接从完整代码堆解释。

固定思想：

```text
完整代码
→ 最小核心
→ 看懂骨架
→ 只增加一层
→ 再增加一层
→ 回到完整项目
```

如果某行再删除就改变核心逻辑，要明确说：

> **这一行是核心，不能再砍了。**

## 4. 六镜头教学法

重要新结构默认从六个角度观察同一个逻辑：

```text
① 正式 Python
② 完整 Lisp 对齐版（涉及 Lisp 时）
③ 局部颜色结构对照
④ 人话执行流程
⑤ 树 / 层级 / 结构图
⑥ 真实数据跑一轮
```

卡住时再加两个诊断镜头：

```text
压缩版 ↔ 展开版
正向执行 ↔ 逆向追踪
```

完整规则见 `docs/TEACHING_SOP.md`。

## 5. 固定语义颜色

教学颜色表示逻辑角色，不等于 PyCharm / ChatGPT 的语法高亮。

| 标记 | 角色 |
|---|---|
| 🟦 | 功能 / 函数名字 |
| 🟩 | 输入 / 参数 |
| 🟨 | 处理 / 表达式 |
| 🟥 | 输出 / 返回结果 |
| 🟪 | 循环 / 条件 / 控制结构 |
| 🟧 | 数据容器 / 局部变量 / 状态 |

原则：

> **同一个结构角色，同一种教学颜色。**

Python、Lisp、伪代码、结构树和数据流图都沿用同一套语义颜色。

## 6. 视觉化与比喻

复杂概念优先尝试画出来：

```text
箭头 → 数据流
树 → 嵌套 / 归属
盒子 → 变量 / list / 容器
表格 → Rank × Suit 组合
流水线 → 函数处理链
时间轴 → 循环一轮一轮执行
```

可按知识点选择 1～3 个生活比喻：

```text
🏭 工厂 / 流水线 → 函数与函数组合
👨‍🍳 厨房 / 菜谱 → 参数 / 处理 / return
🚚 快递 / 物流 → 参数传入与返回值
📦 盒子 / 仓库 → 变量 / list / 作用域
🎭 临时工牌 → 循环变量 / 参数绑定
🎰 组合表格 → 两层循环 / 笛卡尔积
🧩 乐高 → 模块化 / 小函数组成大功能
🗺️ 房间 / 地图 → 层级 / 作用域
🧠 数学函数 → 输入 → 处理 → 输出
```

比喻只负责建立直觉，最后必须回到真实代码。

## 7. Python ↔ Lisp 原则

Lisp 不从零重新追 Python。

```text
Python 学到哪里
→ Lisp 直接对齐到哪里
```

每次涉及 Lisp，默认同时有：

```text
局部最小核心
+
当前 Python 进度完整对齐的 Lisp 全代码
```

原则：

> **局部版负责学懂，完整版负责不迷路。**

Python 仍是项目正式实现；Solver、Dataset、NumPy、PyTorch、GPU AI 默认继续走 Python。

## 8. 代码展示原则

正式可运行代码放上面并保持干净。

代码下面再放：

```text
运行结果
人话执行流程
颜色骨架
结构图
真实数据一轮
为什么这样写 / 不这样写会怎样
```

不默认把大量教学注释塞进正式代码。

## 9. 掌握与验证

严格区分：

```text
已讲解
已理解
预期可运行
实际运行验证
```

只有用户贴出结果或明确确认实际运行成功，才能记录为“已验证”。

抽查一次只问 1～2 个已经讲过的问题，不出陷阱题。

真正掌握优先看：

```text
认出骨架
→ 预测结果
→ 解释原因
→ 展开真实一轮
→ 知道删掉一行会怎样
→ 相似例子还能迁移
```

## 10. 信息负担原则

完整 SOP 是工具箱，不是每节课全部堆给用户。

```text
简单概念 → 正式代码 + 最小核心 + 人话 + 真实一轮
重要新结构 → 尽量完整六镜头
用户卡住 → 加比喻 / 树图 / 展开 / 逆向追踪
用户已懂 → 立即继续，不重复旧课
```

详细执行标准统一以：

`docs/TEACHING_SOP.md`

为准。
