# 项目式学习方法

更新时间：2026-08-09

## 0. 永远不要忘记最终目标

本项目学习 Python 不是为了“学完一门语言”，最终目标始终是：

> **用 Python 做出一个类似 Solver 的 Poker GTO 智能系统。**

以后所有学习内容都要回答：

> **这个知识怎样通过 Python 帮助最终 Poker Solver-like AI？**

如果当前和目标没有明显关系，不主动扩展。

路线：

```text
Python 基础
→ Poker 数据结构
→ Card / Range / Action / State
→ Solver 数据读取与自动化
→ Dataset
→ NumPy / PyTorch
→ 模型训练与评估
→ Game Tree / CFR
→ 推理与决策
→ 类 Solver 的 Poker GTO 智能系统
```

## 1. 只用 Python 教学

正式编程教学只使用 Python。

- 不再使用 Lisp / S-expression。
- 不为了类比引入第二门编程语言。
- 卡住时改用更小 Python、人话、真实数据、箭头、树、盒子、表格、展开 / 压缩、正向 / 逆向追踪。
- 所有正式 AI / 工程实现最终回到 Python。

## 2. 核心哲学：Code drives learning

> **代码是推动课程与项目的第一动力。**

人工智能最终要通过代码实现，所以不把代码当理论课最后的“例子”，而是让代码成为知识出现的入口。

```text
SHOW CODE
→ 读代码
→ 遇到问题
→ 补当前需要的知识
→ 回到代码验证
→ 接入 Poker AI
→ 下一段代码继续推进
```

项目进度优先用下面的问题衡量：

> **今天又读懂、写出、运行或验证了哪段 Python？**

而不是：

> 今天又看完了多少理论？

## 3. Code-first，但不是过度极简

代码尽量先出现，解释紧跟代码。

默认教学密度为**中高**：

- 先给最小核心代码。
- 把当前代码讲清楚。
- 顺手补一层紧邻后续信息。
- 让用户不仅知道“现在是什么”，也大致知道“下一步会长成什么”。
- 不一次铺开整章，也不采用过度稀疏的挤牙膏模式。

## 4. 代码识字能力是基础能力

目标不仅是懂程序逻辑，还要逐渐做到：

> **看到 Python 代码表面，就能读出大部分元素是什么。**

因此教学经常辅助识别三类信息：

```text
① PyCharm 颜色
② 代码单词 / token 属性
③ Python 符号 / 标点
```

例如：

```text
def      → Python 关键字
rank     → 参数 / 变量名
append   → list 方法
"As"     → 字符串字面量
[]       → 当前上下文中的 list / 下标 / 切片
()       → 当前上下文中的调用 / 参数 / 分组等
{}       → 当前上下文中的 dict / set
=        → 赋值
==       → 比较是否相等
.        → 访问对象属性 / 方法
```

尤其注意：**符号必须结合上下文解释。** `[]` 不能永远死背成“列表”。

## 5. PyCharm 颜色以实际显示为准

用户主要使用 PyCharm。

- 颜色如果出现，应直接落到真实代码 token 上。
- 不另造“函数一定蓝、参数一定绿”之类固定语义配色。
- 用户给出 PyCharm 截图 / 配色设置时，以实际显示为 Source of Truth。
- 未知当前配色时，不猜具体颜色名称，但仍解释 token 是关键字、函数名、参数、变量、字符串、方法、类等哪一类。
- 新 token、新结构、容易混淆处经常提醒；刚讲过的不机械复读。

## 6. 最小核心递增法

看不懂时先缩代码：

```text
真实代码
→ 最小核心 Python
→ 读懂代码表面
→ 颜色 / token / 符号
→ 功能 / 输入 / 处理 / 输出
→ 真实值跑一轮
→ 逐层还原
→ 回到项目
```

如果某行再删除就破坏核心逻辑，要明确说：

> **这一行是核心，不能再砍了。**

简化不能改变真实逻辑。

## 7. 四个骨架问题

每个函数优先识别：

```text
功能名字
输入
处理
输出
```

再看：

```text
谁调用它
数据从哪里来
结果到哪里去
它属于 Poker AI 的哪个更大功能
```

Dataset、Model、Loss、推理、CFR、Game Tree 都继续沿用这套骨架。

## 8. 名字来源要标清

遇到新词时顺手说明：

```text
def / return / for = Python 关键字
print / len = Python 内置函数
append = list 自带方法
__init__ = Python 特殊方法
card / rank / deck = 程序员自己起的名字
```

重点形成两个判断：

> **这个必须这么写吗？这个名字能不能换？**

## 9. 真实数据与数据流

抽象代码尽量拿真实 Poker 数据跑一次。

例如：

```text
"A" → rank
"s" → suit
→ create_card
→ "As"
→ deck
```

以后 Dataset、Tensor、Model Input、Policy、EV 都用同样的数据流思维理解。

## 10. 同名变量避免制造假联系

两个变量不是同一个变量但同名容易误导时，教学示例先用不同语义名字，例如：

```text
local_deck
received_deck
```

真正连接变量的是赋值、参数传递、`return`、容器写入等数据流，不是名字一样。

## 11. 数学和 AI 按代码需要出现

不为了“完整课程”提前堆理论。

```text
Python 代码出现需求
→ 补最少必要数学 / AI 概念
→ 马上用 Python 表达
→ 跑数据
→ 看输出
→ 接回 Poker AI
```

例如：

```text
百分数        → Range Frequency
概率          → Strategy
组合          → 1326 Combos
加权平均      → Range EV
向量          → Policy / Range
矩阵          → Batch / Dataset
函数          → Model(x) = y
误差          → Loss
导数          → Gradient
概率分布      → Softmax
条件概率      → Range Update
博弈树 / Regret → CFR
```

## 12. 每次学习都变成项目资产

每次课程尽量留下：

- Python 代码
- 测试
- 数据样本
- 模型
- 实验记录
- 文档
- 当前进度更新

每完成一个可验证小步骤，优先更新 `CURRENT_STATE.md`。

## 13. 一句话路线

> **SHOW CODE；让 Python 代码成为课程与项目的第一动力；用 PyCharm 颜色、代码属性、`[]` / `()` / `{}` 等符号、功能输入处理输出和真实数据帮助读懂；教学保持中高密度，当前代码讲清后顺手多给一层紧邻后续；每学会一点都放回 Poker AI 项目，最终做出类似 Solver 的智能系统。**
