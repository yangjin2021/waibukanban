# Poker GTO Intelligence — 教学连续性协议

本文档规定以后“继续项目 / 教我下一阶段”时必须遵守的固定流程。目的：即使切换聊天页面、会话或模型，也能通过 GitHub 恢复项目上下文，而不是依赖临时聊天记忆。

## 1. 项目事实来源

GitHub 仓库 `yangjin2021/waibukanban` 是项目的长期事实来源（Source of Truth）。

继续项目时优先读取：

1. `PROGRESS.md` — 当前大阶段与真实完成状态
2. `EXECUTION_PLAN.md` — 当前 Sprint / 小任务
3. `ENVIRONMENT.md` — 本机环境、路径与硬件状态
4. `PROJECT_MAP.md` — 00–19 长期路线
5. `docs/INPUT_OUTPUT_SPEC.md` — 输入 / 输出规范
6. `docs/TECHNICAL_CONSTITUTION.md` — 长期技术原则
7. `docs/LEARNING_METHOD.md` — 教学方法
8. `docs/TROUBLESHOOTING.md` — 已遇到的 Bug / 排错经验

如聊天内容与 GitHub 状态冲突，以最新且经过验证的 GitHub 进度记录为准；必要时先核对实际运行结果再更新。

## 2. 用户说“教我下一阶段 / 继续项目”时的固定开场

每次必须先显示两张进度地图：

### A. 大地图

显示 Phase 00–19 的总体进度，至少包含：

- `●` 已完成
- `◐` 当前阶段
- `○` 未开始
- 当前所处 Phase 名称
- 下一大阶段名称

### B. 小地图

显示当前 Sprint / 当前阶段内部任务：

- 已完成步骤
- 当前正在做的步骤
- 接下来 1–3 个步骤
- 当前阶段的过关标准
- **终端起点 / 回到项目命令**
- **当前代码定位信息**

### C. 终端起点规则

不能假设用户仍停留在上一次的 `C:\PokerGTOAI` 目录。用户可能刚打开新的 CMD / PowerShell，甚至当前在 D 盘或 `System32`。

因此，每次继续教学时，小地图必须先给出“从任意新终端回到项目”的命令。

如果是 **CMD**：

```cmd
cd /d C:\PokerGTOAI
```

`/d` 的作用是：即使当前在 D: / E: 等其他盘，也同时切换盘符和目录。

如果是 **PowerShell**：

```powershell
cd C:\PokerGTOAI
```

然后再给出打开文件、当前代码、运行命令。

当前代码定位信息必须尽量包含：

```text
终端起点：任意目录
CMD 回到项目：cd /d C:\PokerGTOAI
PowerShell 回到项目：cd C:\PokerGTOAI
当前文件：C:\PokerGTOAI\src\main.py
打开命令：notepad .\src\main.py
当前代码：
card = "Kh"
print(card)
print("card")
运行命令：python .\src\main.py
预期输出：
Kh
card
```

也就是说，以后“小地图”不能只告诉用户“学到变量 / Rank / Suit”，还必须同时显示：

1. **如果刚开新终端，第一条命令是什么**；
2. **代码在哪个文件**；
3. **当前文件里应该是什么关键代码**；
4. **输入什么命令打开 / 运行**；
5. **预期输出是什么**。

这样用户可以从一个全新的 CMD / PowerShell 直接恢复到当前课程，不需要回翻聊天记录。

然后再开始本次教学内容。

## 3. 每次课程结束时

完成可验证步骤后：

1. 更新 `PROGRESS.md`
2. 更新 `EXECUTION_PLAN.md`
3. 环境变化则更新 `ENVIRONMENT.md`
4. 真实 Bug / 排错结果更新 `docs/TROUBLESHOOTING.md`
5. 关键技术决定变化则更新相应 docs
6. 明确告诉用户：本次完成了什么、下一步是什么

不以“看过了 / 听懂了”直接标记完成；以运行结果、能解释、能手算或能验证为准。

## 4. 换聊天页面 / 换会话 / 换模型

新的对话上下文可能没有上一页聊天细节，因此不能假设记忆完整。

正确恢复方式：

```text
用户：继续 Poker GTO Intelligence / 教我下一阶段
        ↓
读取 GitHub 项目状态
        ↓
恢复大地图 + 小地图 + 终端起点 + 当前代码定位
        ↓
确认当前环境 / 最近完成产物
        ↓
从下一步继续
```

如果当前模型 / 会话暂时无法访问 GitHub，则明确说明无法读取仓库，而不是猜测进度；用户可再次提供仓库链接或关键文件内容后继续。

## 5. 教学风格固定规则

- 用户按零基础学习，不默认懂编程、数学或 AI 术语。
- 每个知识点先讲“项目为什么需要”，再讲直觉，再补最少数学 / Python。
- 每次代码量尽量小，优先 10–30 行以内的可理解增量。
- 新知识必须尽快进入 Poker 项目，而不是脱离项目刷教材。
- 每次明确区分：概念、代码、项目产物、验证结果。
- PowerShell 命令与 Python 代码必须明确分开标注，避免再次混淆解释环境。
- 不假设当前工作目录；每次从“任意新终端”也能恢复。

## 6. 当前项目约定

项目不是现场运行 CFR 的 Solver，而是学习 Solver 输出的快速 GTO 决策智能：

```text
牌局状态参数
  ↓
训练好的神经网络
  ↓
Combo 级 Policy + EV + Range 相关结果
```

底层保持 Combo 级精度，上层可展示 13×13 Range、Combo 明细、牌面频率、EV 和 API 数据。
